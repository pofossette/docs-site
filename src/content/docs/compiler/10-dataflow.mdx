# 10. 全局数据流分析：洞察变量的生老病死

> “编译器不能只盯着眼前的一行代码，它必须有一双穿透所有分支与循环的全知之眼，看清每一个变量在时空长河中的诞生、使用与消亡。”

在前一章中，我们了解了代码在物理内存中的运行环境。而在编译器进行高阶代码优化（例如将变量分配给高速寄存器、删除从未执行的死代码、跨函数传播常数）之前，它必须首先回答一系列全局性的关键问题：
* 在这一行代码处，变量 $x$ 之前的值未来还会被用到吗？（如果不会，存放它的寄存器就可以立刻借给别人！）
* 表达式 $a + b$ 之前是否在所有可能执行的路径上都已经被算过了？（如果是，我们直接拿旧结果复用，省掉昂贵的加法！）
* 这个变量的值到底来自哪一次赋值？是否存在未初始化就直接读取的严重漏洞？

回答这些全局性问题的一整套经典数学理论与算法框架，就是**数据流分析（Dataflow Analysis）**。

---

## 1. 控制流图（CFG）与基本块划分算法

进行数据流分析的前提，是将扁平线性的三地址指令序列转化为具有拓扑分支结构的**控制流图（CFG, Control Flow Graph）**。

### 什么是基本块（Basic Block）？
基本块是满足如下铁律的单入口、单出口连续指令序列：
1. **只能从第一条指令进入**（中途绝不允许有任何分支跳入）；
2. **只能从最后一条指令离开**（中途绝不允许发生任何分支跳出）。

### 基本块划分两步黄金法则

**第一步：寻找所有基本块的首指令（Leaders）**
1. 程序的**第 1 条指令**是首指令；
2. 任何条件/无条件转移指令的**目标指令**（Target）是首指令；
3. 紧跟在转移指令**后面的那一条指令**（Fall-through）也是首指令。

**第二步：构建基本块并连边**
* 每个首指令及其后续指令，直到下一个首指令之前（或程序结尾），组成一个独立基本块 $B$；
* 若基本块 $B_1$ 的最后一条指令能跳转到 $B_2$，或者 $B_1$ 顺序紧随其后且末尾不是无条件跳转，则连有向边 $B_1 \to B_2$。

---

## 2. 数据流分析通用框架与半格理论

数据流分析的本质，是在控制流图上建立一组联立方程组，并通过**迭代（Iteration）** 求解其**不动点（Fixed Point）**。

### 核心要素四大金刚

1. **分析方向（Direction）**：
   * **前向分析（Forward）**：沿控制流方向顺流而下（从 Entry 向 Exit），如到达定值、可用表达式。
   * **后向分析（Backward）**：逆控制流方向逆流而上（从 Exit 向 Entry），如活跃变量分析。

2. **交汇操作（Meet Operator $\wedge$ / $\sqcup$）**：
   * **并集（$\bigcup$，May 分析 / 可能成立）**：只要**至少有一条路径**满足条件即可。例如到达定值（只要某条路径能到达就可能到达）、活跃变量（只要未来任一分支还需要就必须存活）。
   * **交集（$\bigcap$，Must 分析 / 必然成立）**：必须在**所有可能路径**上全部满足才安全。例如可用表达式（必须所有路径都算过才敢放心复用，否则会引发算术错误）。

3. **转移方程（Transfer Function）**：
   描述程序语句在基本块内部对数据流事实的改变：
   * 前向方程：
     $$OUT[B] = gen_B \cup (IN[B] - kill_B)$$
     $$IN[B] = \bigwedge_{P \in pred(B)} OUT[P]$$
   * 后向方程：
     $$IN[B] = use_B \cup (OUT[B] - def_B)$$
     $$OUT[B] = \bigwedge_{S \in succ(B)} IN[S]$$

4. **半格收敛性保障**：
   因为程序状态集合是有限的，且转移函数具有**单调性（Monotonicity）**，根据塔斯基不动点定理（Knaster-Tarski Theorem），从极值边界出发不断迭代，**必定在有限步内单调收敛到最大不动点（MFP）**，绝不可能发生无限死循环！

## 3. 经典数据流分析“三剑客”深度横评

| 维度 | 到达定值 (Reaching Definitions) | 活跃变量 (Live Variables) | 可用表达式 (Available Expressions) |
| :--- | :--- | :--- | :--- |
| **物理直觉** | “哪里的赋值定值能传递到这里？” | “当前变量的值未来是否还会被读取？” | “这个表达式此前是否在所有路径上都算过？” |
| **分析方向** | **前向 (Forward)** | **后向 (Backward)** | **前向 (Forward)** |
| **交汇算子** | **$\bigcup$ (并集，May)** | **$\bigcup$ (并集，May)** | **$\bigcap$ (交集，Must)** |
| **边界条件** | $OUT[\text{Entry}] = \emptyset$ | $IN[\text{Exit}] = \emptyset$ | $OUT[\text{Entry}] = \emptyset$ |
| **其余块初始值**| $\emptyset$ (空集，逐步增大) | $\emptyset$ (空集，逐步增大) | **$U$ (全集，逐步收紧！)** |
| **核心转移公式**| $OUT[B] = gen_B \cup (IN[B] - kill_B)$ | $IN[B] = use_B \cup (OUT[B] - def_B)$ | $OUT[B] = e\_gen_B \cup (IN[B] - e\_kill_B)$ |
| **工业级应用** | 未初始化变量警告、常数折叠、Def-Use 链 | **物理寄存器分配**、**死代码消除** | **全局公共子表达式消除 (Global CSE)** |

<Aside type="note" title="关键原则">

**为什么可用表达式必须初始化为全集 $U$？**  
因为它的交汇算子是**交集 $\bigcap$**！如果把初始值设为空集 $\emptyset$，任何集合与空集求交集永远是空集，算法将直接“死锁”在空集上，找不到任何可复用的公共子表达式。必须先乐观地假设“全集可用”，再通过交集逐步过滤剔除不安全的表达式。

</Aside>

## 4. 交互式推演：4 块控制流图活跃变量后向迭代演算

下面我们针对一个包含循环的经典 CFG，推导演算活跃变量（Live Variables）的后向迭代全过程：

```c
// 对应源码逻辑：
// B1 (Entry): i = 1; j = 1;
// B2 (Loop Header): if (i > 10) goto B4;
// B3 (Loop Body): j = j + i; i = i + 1; goto B2;
// B4 (Exit): return j;
```

各基本块的局部引用的 $use$ 与覆盖定值的 $def$ 为：
* $B_1: use = \emptyset, \; def = \{i, j\}$
* $B_2: use = \{i\}, \; def = \emptyset$
* $B_3: use = \{i, j\}, \; def = \{i, j\}$
* $B_4: use = \{j\}, \; def = \emptyset$
