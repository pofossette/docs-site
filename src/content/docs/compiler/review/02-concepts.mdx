## 模块一：编译系统架构与程序语言基础（第 1 ~ 2 讲）

| 术语名称 | 英文对应 | 形式化定义 / 核心内涵 | 应用场景与高频考点 |
| :--- | :--- | :--- | :--- |
| **翻译程序** | Translator | 将某种语言书写的程序（源语言）等价地转换成另一种语言程序（目标语言）的计算机软件系统。 | 包含编译程序、解释程序、汇编程序，是编译器的上位总称。 |
| **编译程序** | Compiler | 将高级程序设计语言编写的源程序**完整翻译**成机器语言或汇编语言目标程序的翻译程序。 | 典型特点：**执行前统一翻译**，运行速度快，脱离源语言环境独立执行。 |
| **解释程序** | Interpreter | **逐句分析并执行**源语言程序的翻译程序，不生成独立的目标机器代码。 | 跨平台好、交互性强，但运行效率因边解释边执行而显著低于编译程序。 |
| **前端与后端** | Front-end & Back-end | **前端**：与源语言强相关，包含词法、语法、语义分析及与机器无关的中间代码生成；<br />**后端**：与目标机强相关，包含代码优化、寄存器分配与目标机器指令生成。 | 解耦前后端是现代工业级编译器（如 LLVM、GCC）支持 $M$ 种语言到 $N$ 种架构的核心架构设计。 |
| **遍（趟）** | Pass | 编译程序对源程序或其中间表示形式**从头到尾完整扫描一次**并完成指定处理阶段的过程。 | 遍数多可减少内存占用，但会增加频繁的文件/内存 I/O 开销。现代编译器常采用前端单遍/多遍、中后端多 Pass 流水线。 |
| **语法、语义与语用** | Syntax, Semantics & Pragmatics | **语法**：语言符号结构的形态规则（怎样的符号组合是合法的）；<br />**语义**：语言成分所代表的逻辑含义与运算行为；<br />**语用**：符号及其含义在特定执行环境或人类交互中的实际应用关系。 | 编译前端的核心任务是**依据语法验证结构，通过语义规则生成动作**。 |

## 模块二：形式文法、推导与语言分类（第 3 讲）

| 术语名称 | 形式化表示 | 严格定义 / 数学描述 | 重点辨析与易错提示 |
| :--- | :--- | :--- | :--- |
| **文法四元组** | $G = (V_N, V_T, P, S)$ | $V_N$：非终结符非空有限集；$V_T$：终结符非空有限集（$V_N \cap V_T = \emptyset$）；$P$：产生式规则有限集；$S \in V_N$：文法开始符号。 | 产生式左部非终结符必须属于 $V_N$；终结符是词法分析生成的 Token。 |
| **直接推导** | $\alpha A \gamma \Rightarrow \alpha \beta \gamma$ | 设 $A \to \beta \in P$，将串中的非终结符 $A$ 用产生式右部 $\beta$ 替换的过程。 | 步数推导记为 $\Rightarrow^+$（至少一步），零步或多步推导记为 $\Rightarrow^*$。 |
| **最左推导** | $\Rightarrow_{lm}$ | 在推导序列的每一步中，**总是替换最左侧的非终结符**。 | **对应自顶向下语法分析**（LL分析器）；自底向上的规范规约的最右推导逆过程。 |
| **最右推导（规范推导）** | $\Rightarrow_{rm}$ | 在推导序列的每一步中，**总是替换最右侧的非终结符**。 | **最右推导被称为“规范推导”**；其逆过程被称为“规范规约”。 |
| **句型与句子** | Sentential Form & Sentence | **句型**：从开始符号 $S$ 出发能推导出的任意符号串 $\alpha \in (V_N \cup V_T)^*$；<br />**句子**：**仅由终结符构成**的句型，即 $w \in V_T^*$ 且 $S \Rightarrow^* w$。 | 句子一定是句型，但句型不一定是句子（只要含有非终结符就不是句子）。 |
| **文法的语言** | $L(G)$ | 文法 $G$ 所能推导出的**所有句子的集合**：$L(G) = \{ w \in V_T^* \mid S \Rightarrow^+ w \}$。 | 两文法等价是指 $L(G_1) = L(G_2)$。 |
| **语法分析树** | Parse Tree | 推导过程的树形几何表示：根节点为 $S$，内部节点为非终结符，叶节点自左至右构成句型。 | 语法树只反映嵌套派生关系，不区分推导时的替换次序。 |
| **二义性文法** | Ambiguous Grammar | 若对于文法 $L(G)$ 中的**某个句子，存在两棵不同的语法分析树**（或存在两个不同的最左/最右推导），则称该文法是二义性的。 | **文法二义性在理论上是不可算法判定（Undecidable）的**！只能通过改写消除或算符优先级规则人工打破。 |
| **Chomsky 文法分类** | 0/1/2/3 型文法 | - **0型（无限制短语结构文法）**：$\alpha \to \beta$（$\alpha \neq \epsilon$），对应图灵机；<br />- **1型（上下文有关文法 CSG）**：$|\alpha| \le |\beta|$ 或 $\alpha A \gamma \to \alpha \beta \gamma$；<br />- **2型（上下文无关文法 CFG）**：$A \to \beta$（$A \in V_N$），对应下推自动机（语法分析核心）；<br />- **3型（正规文法 / 正则文法）**：$A \to a B$ 或 $A \to a$，对应有限自动机（词法分析核心）。 | 包含关系：$3型 \subset 2型 \subset 1型 \subset 0型$。词法是 3 型，语法是 2 型。 |

## 模块三：句型结构分析与句柄判定（第 11 讲）

<Aside type="tip">

**句型结构三概念是期末大题必考点**！必须依据**语法分析树的几何形状**快速锁定。

</Aside>

| 概念名称 | 基于语法树的判定标准 | 代数推导严格定义 | 考试直观判定口诀 |
| :--- | :--- | :--- | :--- |
| **短语 (Phrase)** | 某一子树的所有叶子节点自左至右连成的边缘符号串。 | 若 $S \Rightarrow^* \alpha A \delta$，且 $A \Rightarrow^+ \beta$，则 $\beta$ 是句型 $\alpha \beta \delta$ 相对于非终结符 $A$ 的短语。 | **“任意子树的完整叶子序列”** 就是一个短语。 |
| **直接短语 (Simple Phrase)** | **高度为 2 的子树**（即仅由某非终结符经过一步产生式 $A \to \beta$ 直接派生）的所有叶子串。 | 若 $S \Rightarrow^* \alpha A \delta$，且 $A \Rightarrow \beta$（一步），则 $\beta$ 是直接短语。 | **“由单一产生式一步派生出的叶子”** 是直接短语。 |
| **句柄 (Handle)** | 句型中**最左侧的直接短语**。 | 在规范句型的语法树中，最左边的直接短语。 | **最左直接短语**！是自底向上规约时当前步骤必须立即规约的对象。 |
| **素短语 (Prime Phrase)** | 至少包含一个终结符，并且不再包含任何更小的素短语的短语。 | 算符优先分析法中的规约核心（最左素短语）。 | 含有终结符且不可再向下拆分短语的极小短语。 |

## 模块四：词法分析与有限自动机（第 4 ~ 8 讲）

| 术语名称 | 形式化表示 / 数学定义 | 核心属性与性质 | 对应关键算法 |
| :--- | :--- | :--- | :--- |
| **单词符号 (Token)** | `(class_code, attr_value)` | 词法分析的独立语法单元。例如 `(ID, "counter")`, `(INT, 42)`, `(RELOP, "<=")`, `(KEYWORD, "while")`。 | 词法分析器输出数据结构。 |
| **正规式 (RE)** | $r \in \text{RE}(\Sigma)$ | 描述词法记号集的形式化表示。基础运算：连接 $ab$、或 $a \mid b$、闭包 $a^*$（0或多次）、正闭包 $a^+$（1或多次）。 | 代数定律：结合律、交换律、分配律。 |
| **确定的有限自动机 (DFA)** | $M = (S, \Sigma, \delta, s_0, F)$ | 五元组：状态有限集 $S$、字母表 $\Sigma$、**单值转移函数** $\delta: S \times \Sigma \to S$、唯一初态 $s_0 \in S$、终态集 $F \subseteq S$。 | 确定性特征：**绝不含 $\epsilon$-转移**，且任一状态面对同一输入字符**至多转移到一个确定的后继状态**。 |
| **非确定有限自动机 (NFA)** | $M = (S, \Sigma, \delta, S_0, F)$ | 转移函数为多值映射 $\delta: S \times (\Sigma \cup \{\epsilon\}) \to 2^S$；可以有**多个初态** $S_0$ 和 $\epsilon$-转移。 | 表达能力与 DFA 等价，但计算机硬件无法直接单步判定，必须确定化为 DFA。 |
| **$\epsilon$-闭包 ($\epsilon\text{-closure}$)** | $\epsilon\text{-closure}(s)$ | 从状态 $s$ 出发，仅经过任意条 $\epsilon$ 弧所能到达的所有状态的集合（含 $s$ 自身）。 | 子集构造法的计算基础：集合 $I$ 的闭包为各状态闭包之并。 |
| **子集构造法** | Subset Construction | 将 NFA 的状态子集映射为 DFA 单一状态的算法。转移方程：$\text{move}(I, a) = \epsilon\text{-closure}(\bigcup_{s \in I} \delta(s, a))$。 | **NFA 确定化为 DFA 的经典算法**。 |
| **DFA 最小化** | DFA Minimization | **Hopcroft 等价分割算法**：将 DFA 状态集合划分为终态 $F$ 与非终态 $S \setminus F$，随后考察对任一字符 $a$，集合内元素转移后是否落在同一子集，若否，则切分为不同子集，直至不再产生分割。 | 消除死状态（不可达状态）与合并等价状态，得到唯一的状态数最简 DFA。 |
| **Thompson 算法** | Thompson's Construction | 基于正规式归纳构造 NFA：为空串、单字符构造基础单元，对连接、选择（分支加 $\epsilon$）、闭包（回跳加 $\epsilon$）组合拼接。 | 构造出的 NFA 状态数至多为正规式符号数的 2 倍。 |

## 模块五：自顶向下语法分析（第 9, 12, 13 讲）

| 术语名称 | 数学公式 / 计算准则 | 产生背景与核心作用 | 判定条件 / 易错点 |
| :--- | :--- | :--- | :--- |
| **左递归** | **直接**：$A \to A \alpha \mid \beta$<br />**间接**：$A \Rightarrow^+ A \alpha$ | 导致自顶向下预测推导陷入无限循环的产生式结构。 | **消除直接左递归公式**：<br />$A \to \beta A'$<br />$A' \to \alpha A' \mid \epsilon$（$\beta$ 不以 $A$ 开头）。 |
| **左公因子** | $A \to \alpha \beta_1 \mid \alpha \beta_2$ | 产生式右部候选式具有相同前缀，使预测分析器面临选择分支盲区。 | **提取左公因子公式**：<br />$A \to \alpha A'$<br />$A' \to \beta_1 \mid \beta_2$。 |
| **$\text{First}$ 集合** | $\text{First}(\alpha) = \{ a \in V_T \mid \alpha \Rightarrow^* a \beta \}$（若 $\alpha \Rightarrow^* \epsilon$，则 $\epsilon \in \text{First}(\alpha)$） | 符号串 $\alpha$ 所能推导出的**所有开头终结符的集合**。 | 若 $X_1 X_2 \dots X_n$，只有当 $X_1 \dots X_{i-1}$ 均为 Nullable 时，$\text{First}(X_i)$ 中的元素才能加入。 |
| **$\text{Follow}$ 集合** | $\text{Follow}(A) = \{ a \in V_T \cup \{\char36 \} \mid S \Rightarrow^* \dots A a \dots \}$ | 在句型中**能够紧跟在非终结符 $A$ 后面的终结符集合**（含输入结束符 `$`）。 | **$\text{Follow}$ 集合绝不能包含 $\epsilon$**！<br />若 $B \to \alpha A$，则 $\text{Follow}(B) \subseteq \text{Follow}(A)$。 |
| **$\text{Select}$ 集合** | 若 $\epsilon \notin \text{First}(\alpha)$：$\text{Select}(A \to \alpha) = \text{First}(\alpha)$；<br />若 $\epsilon \in \text{First}(\alpha)$：$\text{Select}(A \to \alpha) = (\text{First}(\alpha) \setminus \{\epsilon\}) \cup \text{Follow}(A)$。 | 产生式 $A \to \alpha$ 能够被选用的前瞻字符集。 | 构造 LL(1) 分析表的直接依据。 |
| **LL(1) 文法** | 文法的任意非终结符 $A$，若具有多个候选式 $A \to \alpha_1 \mid \alpha_2 \mid \dots \mid \alpha_n$，满足：<br />$\forall i \neq j, \text{Select}(A \to \alpha_i) \cap \text{Select}(A \to \alpha_j) = \emptyset$。 | 允许**自左向右扫描（L）、最左推导（L）、只向前看 1 个符号（1）**即可确定选用哪条产生式的文法。 | **预测分析表 $M[A, a]$ 无多重定义单元格** 是文法为 LL(1) 的充要条件。 |
| **递归下降分析** | Recursive-Descent Parsing | 为每个非终结符编写一个递归函数，依据当前输入符号选择执行分支并递归调用其他子函数。 | 直观高效、语义动作容易嵌入，但必须基于无左递归和无公共因子的文法。 |

## 模块六：自底向上语法分析与 LR 家族（第 10, 11, 14, 15 讲）

| 术语名称 | 形式化表示 / 结构定义 | 算法机制与应用 | 核心对比与性能指标 |
| :--- | :--- | :--- | :--- |
| **拓广文法** | 增设产生式 $S' \to S$ | 引入新开始符号 $S'$，使整个语法分析有唯一的接受状态（当归约到 $S'$ 时停机）。 | 避免原文法开始符号 $S$ 出现在产生式右部造成接受态混淆。 |
| **活前缀** | Viable Prefix | 规范句型的一个前缀，这种前缀**不包含句柄右边的任何符号**（即在自底向上分析栈中合法出现的符号串前缀）。 | LR 分析器的本质就是：**用有限自动机识别活前缀**！ |
| **LR(0) 项目** | $A \to \alpha \cdot \beta$ | 在产生式右部某处标有一个圆点 $\cdot$ 的规则。圆点左边是已压入栈的符号，右边是期望移进的符号。 | 分类：<br />- 移进项目：$A \to \alpha \cdot a \beta$<br />- 待约项目：$A \to \alpha \cdot B \beta$<br />- 规约项目：$A \to \gamma \cdot$<br />- 接受项目：$S' \to S \cdot$ |
| **闭包函数 $\text{CLOSURE}$** | $\text{CLOSURE}(I)$ | 若 $[A \to \alpha \cdot B \beta] \in I$，则将所有形如 $[B \to \cdot \gamma]$ 加入闭包中，直至不动点。 | 从已知项目推导出所有即将展开分析的子规则项目。 |
| **转移函数 $\text{GO}$** | $\text{GO}(I, X) = \text{CLOSURE}(\{ [A \to \alpha X \cdot \beta] \mid [A \to \alpha \cdot X \beta] \in I \})$ | 状态 $I$ 接收文法符号 $X$（终结符或非终结符）后，圆点后移一位所形成的新项目集。 | 构造 LR 项目集规范族 DFA 的转移边。 |
| **SLR(1) 分析** | Simple LR | 当状态中存在移进-规约冲突（$[A \to \alpha \cdot a \beta]$ 与 $[B \to \gamma \cdot]$）时，考察 $\text{Follow}(B)$：若 $a \notin \text{Follow}(B)$，则冲突化解。 | 状态数与 LR(0) 完全相同；若输入 $a \in \text{Follow}(B)$，则 SLR(1) 依然爆发冲突。 |
| **LR(1) 项目** | $[A \to \alpha \cdot \beta, a]$ | 带有搜索符（Lookahead）$a \in V_T \cup \{\char36 \}$ 的项目。表示只有当输入符号为 $a$ 时，归约 $A \to \alpha\beta$ 才合法。 | 搜索符传播：$[A \to \alpha \cdot B \beta, a] \implies [B \to \cdot \gamma, b]$，其中 $b \in \text{First}(\beta a)$。 |
| **同心状态 (Core)** | Core of State | 去除 LR(1) 项目的前瞻符号后，产生式和圆点位置完全相同的状态。 | LALR(1) 算法将所有同心状态进行合并。 |
| **LALR(1) 分析** | Lookahead LR | 将 LR(1) 中具有相同同心核心的状态合并。状态数缩减为与 LR(0) 相同。 | **核心定理**：同心合并**绝不会产生新的移进-规约冲突**，但可能引入新的**规约-规约冲突**。 |

## 模块七：语义分析与属性文法（第 16 ~ 17 讲）

| 术语名称 | 定义与数学模型 | 属性传递方向 | 对应文法分类与求值时机 |
| :--- | :--- | :--- | :--- |
| **综合属性 (Synthesized)** | 节点 $N$ 处的属性值仅由其**子节点**的属性值确定。产生式 $A \to X_1 \dots X_n$，规则形如：$A.s = f(X_1.s, \dots, X_n.s)$。 | **自底向上传递**（从叶子到根）。 | **S-属性文法**：仅包含综合属性。可在自底向上 LR 语法分析的规约阶段同步求值。 |
| **继承属性 (Inherited)** | 节点 $N$ 处的属性值由其**父节点**或**兄弟节点**的属性值确定。规则形如：$X_i.i = f(A.i, X_1, \dots, X_{i-1})$。 | **自顶向下或由左向右传递**。 | 用于类型声明传播（如变量列表中传递类型信息）。 |
| **S-属性文法** | 仅含综合属性的语法制导定义（S-SDD）。 | 纯自底向上。 | LR 语法分析器维护一个平行的“语义栈”，每次规约执行语义代码计算属性。 |
| **L-属性文法** | 允许综合属性和继承属性，但每个产生式中符号 $X_j$ 的继承属性**只能依赖于父节点继承属性或 $X_j$ 左边符号的属性**。 | 依赖图**绝无从右向左的环或向左回流依赖**。 | 可在自顶向下递归下降分析中，将继承属性作为函数入参、综合属性作为函数返回值同步求值。 |
| **依赖图 (Dependency Graph)** | 有向图，节点为分析树中各节点的属性实例，有向边从自变量指向因变量。 | 若存在有向环，则说明属性循环依赖，文法非法。 | 通过**拓扑排序**确定属性实例的合法求值顺序。 |

## 模块八：中间语言与控制流翻译（第 18 ~ 22 讲）

| 术语名称 | 数据表示 / 结构形式 | 作用与功能 | 核心操作与函数 |
| :--- | :--- | :--- | :--- |
| **四元式** | `(op, arg1, arg2, result)` | 经典三地址中间代码形式。操作符 `op`，两个源操作数 `arg1, arg2`，运算结果暂存地址 `result`。 | 硬件无关、便于代码优化调整顺序、数据流依赖清晰。 |
| **数值表示法** | 如 `T1 = a < b` 翻译为判断赋值代码 | 将布尔表达式当作一个计算 0 或 1 整型值的数值运算表达式。 | 用于位运算、布尔变量赋值（如 `bool x = (a > b);`）。 |
| **短路求值** | Short-Circuit Evaluation | 布尔表达式求值时，一旦前序项已能决定整体逻辑真假，后续项立即跳过执行。 | 如 `A && B` 中若 `A` 为假直接跳出；防止数组越界及空指针崩溃。 |
| **悬空跳转与四元式地址** | `(j, _, _, 0)` | 生成跳转四元式时，目标基本块的入口标号尚未生成，故将转移目标暂时置 0。 | 由拉链回填技术在后续完成地址填入。 |
| **拉链回填函数** | - `makelist(i)`：创建仅含四元式 $i$ 的新链；<br />- `merge(p1, p2)`：合并两条待回填链；<br />- `backpatch(p, quad)`：将地址 `quad` 填入链表 $p$ 中所有悬空四元式的目标字段中。 | 解决单遍扫描下前向跳转目标未定的工业级机制。 | `truelist`（真出口链）、`falselist`（假出口链）、`nextlist`（后续代码出口链）。 |

## 模块九：运行时存储空间组织与过程调用（第 23 ~ 24 讲）

| 术语名称 | 内存位置 / 结构组成 | 核心功能与工作机理 | 关键考点与辨析 |
| :--- | :--- | :--- | :--- |
| **活动记录 (栈帧)** | 临时变量、局部变量、机器状态保护、**访问链 (静态链)**、**控制链 (动态链)**、实参传递区、返回值。 | 函数或过程单次调用执行所占用的连续内存沙盒。 | 栈增长方向通常向低地址延伸，`SP` 与 `FP` 指针协同维护。 |
| **动态链 (控制链)** | 指针，指向**直接调用者（Caller）**的活动记录基地址。 | 无论语法嵌套如何，函数返回时依据动态链恢复调用者的栈顶。 | **反映运行时的调用栈追踪序列**（Call Stack Trace）。 |
| **静态链 (访问链)** | 指针，指向**外层语法定义者**的活动记录基地址。 | 解决嵌套过程/闭包访问词法作用域外层局部变量的寻址问题。 | **反映编译期源程序的作用域嵌套静态层深**（Static Nesting Depth）。 |
| **传值 (Pass by Value)** | 调用前计算实参的值，将副本压入形参存储单元。 | 被调用函数内无论如何修改形参，**对调用者的实参毫无影响**。 | C/C++ 默认传递机制。 |
| **传地址/引用 (Pass by Reference)** | 将实参变量的**内存物理地址**传给被调用者。 | 形参和实参共享同一物理单元，**对形参的任何赋值立即反映在实参上**。 | C++ 引用传递 `int &x`、Fortran 传递。 |
| **传结果 (Pass by Value-Result)** | 进函数时拷贝实参值；**函数执行完毕退出的瞬间**将形参值回写到实参。 | 具有传值的执行独立性，但在返回瞬间产生延迟副作用。 | Ada 语言 `in out` 参数模式。 |
| **传名 (Pass by Name)** | 将实参表达式以**文本替换**或构造临时函数（Thunk 闭包）的形式传递。 | **每次引用形参时重新计算实参表达式的值**。 | Algol 60 机制；可能引发恶意的“实参晚绑定副作用”（Late Binding）。 |

## 模块十：代码优化与目标代码生成（第 25 ~ 28 讲）

| 术语名称 | 判别规则 / 数学定义 | 核心功能与优化效果 | 适用阶段 |
| :--- | :--- | :--- | :--- |
| **基本块 (Basic Block)** | 单入口、单出口的连续指令序列。入口是首语句，出口是末语句，中间无任何跳转或分支。 | 局部代码优化的基础单位。 | **Leader 入口语句判别三规则**：<br />1. 程序第一条语句；<br />2. 任何条件/无条件转移语句的目标语句；<br />3. 紧跟在条件转移语句后面的语句。 |
| **流图 (CFG)** | 有向图 $G = (V, E)$，节点 $V$ 为基本块，边 $E$ 为控制流转移分支。 | 全局数据流分析与循环优化的拓扑基础。 | 从块末尾跳转或顺序流向下一个块引出有向边。 |
| **DAG 局部优化** | 为基本块构造有向无环图：叶节点为变量/常数初始值，内部节点为操作符，并挂载变量名标签。 | **四大优化效果一体化完成**：<br />1. 消除局部公共子表达式；<br />2. 消除死代码（无后续引用的节点不生成指令）；<br />3. 编译期常数折叠；<br />4. 代数恒等式化简（如 $x+0=x, x \times 1 = x$）。 | 针对单一基本块的局部优化算法。 |
| **自然循环 (Natural Loop)** | 满足唯一入口节点（首节点 Header）支配循环内所有节点，且存在至少一条回跳到 Header 的**回边 (Back Edge)**。 | 编译期识别高频执行热点代码的关键算法。 | **代码外提**（循环不变计算提到循环前）、**归纳变量强度削弱**（乘法变加法）。 |
| **寄存器描述表 (`RVALUE`)** | 记录每个物理寄存器当前正存放着**哪些变量的值**。 | 如 `RVALUE[R0] = {A, B}` 表示寄存器 $R_0$ 中同时保存着变量 $A$ 和 $B$ 的有效值。 | 目标代码生成器核心数据结构。 |
| **地址描述表 (`AVALUE`)** | 记录每个变量当前的值正保存在**哪些物理位置**（如寄存器、内存单元）。 | 如 `AVALUE[A] = {R0, memory_addr_A}`。 | 变量值若仅在寄存器中，被换出时必须写回内存（Store）。 |
